## 共享执行规则

- 开始及提交前检查分支、`git status --short`、`git worktree list` 和基线；不接管其他人的改动。
- 每个 Story 使用从最新已提交代码创建的独立同级 worktree，分支以 `feature/` 开头。
- 人确认意图由 Story 的 `intent_version` 决定。改变认证方法、schema、公开参数、状态所有权、失败语义或验收条件前必须停止并询问。
- 先保存可观察失败，再修复根因。测试验证外部行为，不绑定私有方法或文件写入次数。
- 只在全部 TODO、验收和门禁证据满足后标记 done，并刷新项目进展。
- 完整交接记录起止提交、命令与退出码、固定分母、产物或校验和、数据副作用、清理、Git 状态、阻塞和下一 Story 输入。

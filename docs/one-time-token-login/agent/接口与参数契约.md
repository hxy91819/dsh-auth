# 接口与参数契约

本文冻结企业版 v2 的公开自动化和运行时接口。实现可以调整私有符号，但不得改变本页语义。

## CLI 通用规则

- 命令保留 `setup`、`plan`、`doctor`、`reset-password`、`uninstall`、`hash`、`secret`，新增 `issue-login-token`。
- 全局参数为 `--help`、`-h`、`--version`、`--json`、`--non-interactive`，可以位于命令前后。
- 值参数同时接受 `--name value` 和 `--name=value`。未知参数、重复参数、布尔参数带值、缺值或额外位置参数返回退出码 2。
- `--json` 只选择输出格式。只有 `--non-interactive` 禁止 TTY prompt。
- 保留退出码：0 成功、2 用法、3 前置条件、4 冲突、5 权限、6 执行失败、7 取消、8 不健康。
- 密码只从隐藏 TTY、`--password-stdin` 或绝对 `0600` 普通文件读取。密码不进入 argv；同一命令只能选择一个来源。

## setup 与 plan

以下是 v2 setup/plan 的完整值参数：

| 参数 | 默认或条件 | 语义 |
| --- | --- | --- |
| `--nginx require\|install\|skip` | system 为 `require`；`--output-dir` 为 `skip` | 保留现有 Nginx 策略 |
| `--dsh-service` | system 必填 | 精确 systemd unit |
| `--dsh-home` | 尝试发现 | Harness home 绝对路径 |
| `--dsh-executable` | 尝试发现 | DSH 可执行文件绝对路径 |
| `--profile` | `web` | DSH profile |
| `--package` | `dsh-auth@<CLI version>` | 固定 registry 版本或绝对 tarball |
| `--admin-bootstrap password\|login-token` | 必填 | 显式管理员初始化方式 |
| `--admin-username` | 仅 password 模式必填 | 初始管理员登录名 |
| `--login-token enabled\|disabled` | 必填 | 是否长期开放 token 签发和兑换 |
| `--login-token-error-message-zh` | 可选 | 1–500 字中文失败纯文本 |
| `--login-token-error-message-en` | 可选 | 1–500 字英文失败纯文本 |
| `--password-file` | setup/password 模式来源之一 | 临时密码文件 |
| `--mode https\|http` | `https` | 保留现有边缘模式 |
| `--upstream` | `127.0.0.1:3080` | 回环 Harness upstream |
| `--listen-address` | HTTPS 为 `0.0.0.0`；HTTP 必填 | Nginx 监听字面 IP |
| `--http-port` | HTTPS 为 80；HTTP 为 8080 | HTTP 或重定向端口 |
| `--https-port` | 443 | HTTPS 端口 |
| `--server-name` | HTTPS 必填 | Nginx 公网 hostname |
| `--certificate` | HTTPS 必填 | TLS 证书绝对路径 |
| `--certificate-key` | HTTPS 必填 | TLS 私钥绝对路径 |
| `--output-dir` | 可选 | 容器/离线输出；自动选择 Nginx skip |

布尔参数保留 `--dry-run`、`--authorize-nginx-install`、`--password-stdin`。`plan` 接受同一非秘密请求但拒绝密码来源；它可以在 password 模式生成 ready 计划。`setup` 只有在计划 ready 且模式为 password 时才要求密码来源。

条件规则：

- `password` 要求 `--admin-username` 和 setup 时的一个密码来源；允许 token enabled 或 disabled。
- `login-token` 要求 token enabled，并拒绝管理员用户名和所有密码来源。
- token disabled 时拒绝自定义 token 失败文案。
- 自定义文案逐语言独立可选；缺失语言使用内置文案。值拒绝 C0/C1 控制字符和 Unicode category C。
- 用户名先做 NFC，结果必须为 1–64 个 Unicode code point，不含控制字符或首尾空白；比较区分大小写。
- 管理员密码必须为 15–128 个 Unicode code point且 UTF-8 不超过 1024 字节；不 trim、不规范化、不要求字符组合。
- `--output-dir` 与显式 `--nginx require|install` 冲突；HTTP 仍只允许显式私网、ULA 或回环地址。

删除且不提供别名：`--user-id`、`--username`、`--roles`、`--dsh-bin`、`hash --stdin`。`--dsh-bin` 和 `--stdin` 的错误可以给出新名称，但不得继续执行。

## 令牌签发命令

```text
dsh-auth issue-login-token [--ttl-seconds 60..300]
  [--auth-state-file /absolute/path --public-origin ORIGIN]
  [--non-interactive] [--authorize-login-token-issue] [--json]
```

- 默认 TTL 300 秒。`--ttl-seconds` 只接受 60–300 的十进制安全整数。
- 不提供 `--auth-state-file` 和 `--public-origin` 时为受管 systemd 模式：从 `/etc/dsh-auth/install-state.json` v2 推导路径、public origin、令牌启用状态和服务身份；仅 root 可运行。
- 容器模式必须同时提供两个参数。`--auth-state-file` 必须是调用者拥有或 root 拥有的 `0600` 普通文件，无符号链接；token 目录固定为其父目录下 `login-tokens/`。调用者必须是 root 或状态文件唯一所有者。
- `--public-origin` 必须是单一 `http` 或 `https` origin，不含用户信息、路径、查询或 fragment。HTTP 仅允许私网、ULA 或回环字面地址。
- 两种模式都要求配置 token enabled、令牌目录为真实 `0700` 目录且所有者与认证状态一致。
- TTY 模式展示敏感输出说明并要求输入精确确认词 `issue-login-token`。非交互必须同时传 `--non-interactive` 与 `--authorize-login-token-issue`。
- 人读成功输出只向 stdout 写一行完整登录 URL。错误只写 stderr，不包含 token 或 URL。

token 固定格式为 `dsh_otl_v1_` 加 32 字节 base64url（43 字符）。成功 URL 为 `<public-origin>/auth/token#token=<token>`。当前命令不接受 returnTo；兑换默认进入 `/`。

JSON v2 成功文档为：

```json
{
  "schemaVersion": 2,
  "command": "issue-login-token",
  "status": "success",
  "exitCode": 0,
  "token": "<bearer-secret>",
  "loginUrl": "<public-origin>/auth/token#token=<bearer-secret>",
  "expiresAt": "<ISO-8601 UTC>"
}
```

这是唯一允许在成功 JSON 中返回 bearer secret 的命令。JSON 错误沿用通用 `schemaVersion`、`command`、`status=error`、`exitCode`、`message`、`diagnostics`，不得包含部分生成的 token。

## 其他命令

- `reset-password` 保留 `--password-file`、`--password-stdin`、`--authorize-password-reset`、`--non-interactive`、`--json`。它保留用户名，更新 Argon2id，旋转 session secret，清空全部会话；活动服务必须先停止，成功后恢复，失败按备份回滚。
- `uninstall` 保留 `--dry-run`、`--authorize-uninstall`、`--non-interactive`、`--json`，只删除 v2 ownership record 中的精确路径。
- `doctor` 只接受 `--json`，检查 v2 schema、内容、权限、token 目录、认证状态、session secret、Nginx、systemd 和 profile。
- `hash` 只接受 `--password-stdin`，并执行同一管理员密码长度策略；`secret` 不接受参数。
- 所有非签发命令的 JSON、计划、诊断和失败保持 secret-free，schemaVersion 统一为 2。

## Cordis v2 配置

公网前缀固定 `/auth`。`ConfigInput` 只接受以下字段，未知字段应失败：

| 字段 | 必填/默认 | 约束 |
| --- | --- | --- |
| `authStateFile` | 必填 | 绝对路径，运行时 `0600` 普通文件 |
| `sessionSecretFile` | 必填 | 绝对路径，32–4096 字节秘密材料 |
| `loginTokenEnabled` | false | boolean |
| `loginTokenDirectory` | enabled 时必填 | 绝对路径，必须等于 auth state 同级 `login-tokens` |
| `loginTokenFailureMessageZh` | 可选 | 1–500 字纯文本 |
| `loginTokenFailureMessageEn` | 可选 | 1–500 字纯文本 |
| `secureCookies` | true | boolean |
| `sessionTtlSeconds` | 259200 | 60–2592000 |
| `idleTtlSeconds` | 259200 | 60–session TTL |
| `sessionRenewalSeconds` | 3600 | 1–TTL 与 idle 的较小值 |
| `maxSessions` | 16 | 1–1024 |
| `loginWindowSeconds` | 60 | 1–3600 |
| `loginMaxAttempts` | 5 | 1–100 |
| `loginBlockSeconds` | 300 | 1–86400 |
| `loginTokenWindowSeconds` | 60 | 1–3600 |
| `loginTokenMaxAttempts` | 10 | 1–100 |
| `loginTokenBlockSeconds` | 300 | 1–86400 |
| `trustedProxyAddresses` | loopback v4/v6 | 1–32 个字面 IP |

删除 `basePath`、`userId`、`username`、`roles`、`passwordHash`、`passwordHashFile`、`sessionSecret`、`sessionStoreFile` 和 `maxPasswordBytes`。

安装器环境文件只映射非秘密策略与秘密文件路径：

- `DSH_AUTH_STATE_FILE`
- `DSH_AUTH_SESSION_SECRET_FILE`
- `DSH_AUTH_LOGIN_TOKEN_ENABLED`
- `DSH_AUTH_LOGIN_TOKEN_DIRECTORY`
- `DSH_AUTH_LOGIN_TOKEN_FAILURE_MESSAGE_ZH`
- `DSH_AUTH_LOGIN_TOKEN_FAILURE_MESSAGE_EN`
- 现有 `DSH_AUTH_SECURE_COOKIES`、session、password login limiter、trusted proxy 变量
- 新增 `DSH_AUTH_LOGIN_TOKEN_WINDOW_SECONDS`、`DSH_AUTH_LOGIN_TOKEN_MAX_ATTEMPTS`、`DSH_AUTH_LOGIN_TOKEN_BLOCK_SECONDS`

删除旧用户、角色、密码哈希、字面量 session secret 和 session store 环境变量。

## 受管路径与状态

systemd 安装的关键路径：

| 路径 | 模式与所有者 | 内容 |
| --- | --- | --- |
| `/etc/dsh-auth/install-state.json` | `0600 root:root` | v2 ownership/recovery；无秘密 |
| `/etc/dsh-auth/dsh-auth.env` | `0640 root:<service-group>` | 路径和非秘密策略 |
| `/etc/dsh-auth/session-secret` | `0640 root:<service-group>` | Cookie/session 签名秘密 |
| `/var/lib/dsh-auth` | `0700 <service-user>:<service-group>` | 认证运行状态根目录 |
| `/var/lib/dsh-auth/auth-state.json` | `0600 <service-user>:<service-group>` | 管理员 Argon2id 和会话 |
| `/var/lib/dsh-auth/login-tokens` | `0700 <service-user>:<service-group>` | 摘要 token 文件 |

认证状态 schemaVersion 为 2：

```json
{
  "schemaVersion": 2,
  "secretId": "<HMAC identifier>",
  "administrator": {
    "id": "admin",
    "username": null,
    "passwordHash": null,
    "configuredAt": null
  },
  "sessions": []
}
```

password 初始化从第一版状态开始写入 username、Argon2id 和 configuredAt。每个 session 只保存 43 字符随机 token、`authenticationMethod`（`password` 或 `login-token`）、createdAt、lastSeenAt、expiresAt；用户 ID、角色和用户名在读取时由当前管理员状态派生。

token 文件名仅为原 token SHA-256 的 64 字符小写 hex，不加扩展名。内容仅为 `schemaVersion: 1`、整数毫秒 `issuedAt`、`expiresAt`。签发和兑换开始时都清理严格匹配且已过期的受管文件；临时、抢占和清理文件使用严格固定前缀，任何不匹配文件均不读取、不覆盖、不删除。

## HTTP 与浏览器接口

| 路由 | 方法 | 行为 |
| --- | --- | --- |
| `/auth/token` | GET/HEAD | 返回 no-store fragment 桥接页；不读取或消费 token |
| `/auth/token-bootstrap.js` | GET/HEAD | 同源静态脚本；读取 fragment、清除 history、提交表单 |
| `/auth/token` | POST | 校验 Origin、CSRF、大小和限流后原子兑换；成功写 session Cookie并 303 |
| `/auth/admin/setup` | GET | 仅已认证且管理员未配置时显示首次设置页 |
| `/auth/admin/setup` | POST | 校验 session、Origin、CSRF、用户名和密码后原子设置 |

fragment 只接受一个 `token` 键；未知键或重复键失败。脚本在创建任何含 token 的 DOM 节点或发起 POST 前执行 `history.replaceState` 清除 fragment。页面使用 `Referrer-Policy: no-referrer`、no-store、`frame-ancestors 'none'`、同源外部脚本和 `form-action 'self'`。

token POST 请求体只含 `csrf` 和 `token`。成功且管理员已配置时 303 到 `/`；未配置时 303 到 `/auth/admin/setup?returnTo=%2F`。失败 token 统一返回 401 HTML。独立限流返回 429，错误 CSRF/Origin 返回 403，错误方法返回 405。

管理员设置 POST 含 `csrf`、`returnTo`、`username`、`password`、`confirmPassword`。Later 是指向已校验 returnTo 的普通同源链接，不写状态。已经配置时 GET/POST 均不允许覆盖，返回友好已完成页或重定向到账户页。

# 安全威胁与验收矩阵

每个场景由唯一 Story 主责，STORY-06 在同一 acceptance commit 上复核。证据必须验证外部行为和实际文件/网络边界，不得只断言私有函数调用。

| ID | 威胁或失败 | 必须成立的控制 | 主责 | 主要证据 |
| --- | --- | --- | --- | --- |
| SEC-01 | token 进入查询日志、Referer 或浏览器后续历史 | fragment 传递；GET 不含 token；先 replaceState 再 POST；no-referrer | STORY-04 | 真实浏览器 URL/history、Caddy access log、HTTP 捕获 |
| SEC-02 | token 明文落盘 | SHA-256 文件名；元数据无 token；目录 `0700`、文件 `0600` | STORY-03 | 文件内容/名称/权限行为测试与秘密扫描 |
| SEC-03 | 两个请求同时兑换 | 同目录原子重命名抢占；最多一个 session Cookie | STORY-04 | 并发双 POST 测试，成功数固定 1 |
| SEC-04 | 过期或已用 token 重放 | 先抢占和删除，再创建会话；失败不恢复 | STORY-04 | 过期、重复、会话持久化失败后的二次兑换 |
| SEC-05 | 普通链接预取消费 token | GET 只返回桥接页，不读 token store | STORY-04 | GET/HEAD/预取后 token 仍可由一次 POST 成功消费 |
| SEC-06 | 跨站提交 bearer token | signed CSRF Cookie、精确 Origin/Referer、SameSite、表单 content type | STORY-04 | 缺失、null、跨 origin、坏 CSRF 请求均失败 |
| SEC-07 | returnTo 开放跳转 | 复用 safe absolute-path 校验；issuer 不接受 returnTo | STORY-04 | scheme-relative、反斜线、控制符、超长和外部 origin |
| SEC-08 | 猜测或 DoS | 256 位 token；独立 TS IP limiter；Caddy 请求大小/超时；统一失败 | STORY-04 | 429/retry-after、密码 limiter 不互相污染、大小/超时和状态探针测试 |
| SEC-09 | 恶意状态路径或符号链接 | 绝对路径、realpath、O_NOFOLLOW、类型、所有权、模式、大小检查 | STORY-02 | root/system 与容器路径攻击、symlink swap、宽权限测试 |
| SEC-10 | 签发者越权 | systemd root-only；容器 root 或状态唯一所有者；明确授权 flag | STORY-03 | UID、owner、TTY/noninteractive 组合测试 |
| SEC-11 | 超量或长寿 token | TTL 60–300；最多 32 个有效项；严格过期清理 | STORY-03 | 边界值、第 33 个、过期释放容量、未知文件保留 |
| SEC-12 | token 随机冲突或中途输出失败 | `wx` 临时文件和原子 rename；冲突重试；失败输出不泄密 | STORY-03 | 注入 RNG 冲突、写入/rename/stdout 失败 |
| SEC-13 | 自定义文案 XSS 或 header 注入 | 1–500 字纯文本、控制字符拒绝、HTML 转义 | STORY-04 | HTML 特殊字符、CRLF、Unicode C 类、语言回退 |
| SEC-14 | 管理员首次设置竞态覆盖 | 认证状态内 compare-unset + 单次原子 mutate | STORY-05 | 两个并发 POST，只有一个 username/hash 生效 |
| SEC-15 | 早期 bootstrap 会话长期存活 | 首次设置保留当前 token session，撤销其他 session | STORY-05 | 三会话场景，当前 200、其他 401、重启后不恢复 |
| SEC-16 | 密码过弱或被静默改变 | 15–128 code point、1024 bytes、确认、无 normalize/trim、Argon2id | STORY-01/05 | Unicode、空白、边界长度、确认不一致、验证测试 |
| SEC-17 | 状态写入撕裂或回滚不完整 | 同目录 temp、`0600`、fsync、rename、父目录 fsync、内存快照回滚 | STORY-01 | 写/fsync/rename 故障注入、重启加载旧完整状态 |
| SEC-18 | 外部 reset 与运行服务争写 | 活动服务先停再改状态/secret，成功恢复，失败回滚 | STORY-02 | active/inactive、stop/start/rollback 失败矩阵 |
| SEC-19 | secret 轮换后旧状态复活 | auth state 记录 secretId；不匹配时清空 session，保留管理员凭据 | STORY-01 | secret 轮换重启，旧 Cookie 401，密码仍可登录 |
| SEC-20 | 旧 schema 被误改或当作 v2 | v1 明确 conflict；不自动写、不读取旧会话 | STORY-02 | v1 system/output state、doctor/setup/reset/uninstall 行为 |
| SEC-21 | JSON、计划、错误泄密 | 仅签发成功 JSON/URL可含 token；所有失败和其他命令 secret-free | STORY-02/03 | 捕获 stdout/stderr/JSON/plan/diagnostics 并扫描 |
| SEC-22 | Caddy 绕过或 `/auth/verify` 暴露 | Caddy 是唯一公网 listener；Harness 回环；公开 verify 404 | STORY-01.1 | Caddy 检查、直接公网 404、受保护 HTTP/SSE/WS/download |
| SEC-23 | Cookie 或续期策略分叉 | 两种登录调用同一 SessionStore create/authenticate | STORY-01/04 | Cookie flags、72h、idle、renewal、logout、max session |
| SEC-24 | 服务重启改变一次性或会话语义 | token 文件独立持久；auth state 原子加载；过期和撤销保持 | STORY-01/04 | 签发后重启再兑、兑换后重启重放、会话重启恢复 |
| SEC-25 | 发布包或 Git 留下真实敏感信息 | 生成测试材料、固定 redaction 扫描、pack 内容审计 | STORY-06 | `npm pack --dry-run`、文件与 Git metadata 扫描 |
| SEC-26 | 主包中的 Caddy 缺失、篡改、错架构或来源漂移 | 主包同时携带两架构；版本、manifest、官方/项目 SHA-256 和许可证安装前校验 | STORY-02 | x64/ARM64 选择、缺失、错架构、篡改和单包离线安装测试 |

## 功能验收场景

| ID | 场景 | 预期结果 | 主责 |
| --- | --- | --- | --- |
| FUN-01 | password setup | 管理员用户名和密码写入 v2 状态，密码登录成功 | STORY-02 |
| FUN-02 | login-token setup | 不读取密码，管理员未配置，签发命令可用 | STORY-02 |
| FUN-03 | token disabled | 签发拒绝，GET/POST `/auth/token` 为 404 | STORY-02/04 |
| FUN-04 | 首次 token 登录完成设置 | 会话建立，设置页出现，提交后返回 Harness并可密码登录 | STORY-05 |
| FUN-05 | 首次 token 登录选择 Later | 临时 username 为 admin，本次进入 Harness，下次 token 再提示 | STORY-05 |
| FUN-06 | 已配置管理员 token 登录 | 直接进入 Harness，不再显示首次设置页 | STORY-04/05 |
| FUN-07 | systemd 签发 | 从 install-state 推导 origin 和路径，输出正确 URL/JSON | STORY-03 |
| FUN-08 | 容器签发 | 显式 auth state/public origin 产生同形输出并可兑换 | STORY-03/06 |
| FUN-09 | 自定义失败语言 | zh/en 按 UI preference 选择，缺失项回退内置文案 | STORY-04 |
| FUN-10 | 旧版升级 | 所有相关命令给出卸载重装说明，原文件和服务不被自动改动 | STORY-02/06 |
| FUN-11 | latest Harness 兼容 | npm latest 与精确锁定一致，隔离安装后同一真实 E2E 通过 | STORY-06 |
| FUN-12 | Caddy 主包分发 | 一个主包同时携带 linux x64/ARM64 Caddy，按当前架构安装且不下载二进制 | STORY-02/06 |
| FUN-13 | 两种 TLS | automatic 通过本地 ACME 验收，manual 使用 credentials 证书并通过 HTTPS/HTTP2 | STORY-02 |

## 证据位置

- HTTP、CSRF、Cookie、错误和 returnTo：`tests/auth-http.spec.ts` 及新增 token/onboarding 行为测试。
- 状态、并发、重启和故障注入：`tests/session-persistence.spec.ts` 及新增 auth-state/token-store 测试。
- CLI、路径、权限、计划、JSON、doctor、reset、uninstall：`tests/installer-*.spec.ts`。
- Caddy 公网边界、请求限制和 protected routes：`check:caddy`、Caddy E2E 与性能 runner。
- 浏览器 fragment、history、Later 和设置流程：`scripts/real-integration.mjs` 生成的隔离证据。
- 发布包、秘密和元数据：STORY-06 执行卡记录命令、退出码、产物清单和扫描结论。

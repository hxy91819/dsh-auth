# 核心决策

以下决策是所有 Story 的共同边界。实现发现新事实时，先更新 Story blocker；未经用户明确授权不得自行改变。

| ID | 决策 | 理由与结果 |
| --- | --- | --- |
| D-01 | 企业版使用破坏性 v2，不兼容或迁移 v1 | 项目尚未冻结企业契约；一次清除单账号遗留比长期维护双 schema 更安全。升级要求卸载、重新 setup，旧会话失效 |
| D-02 | 管理员 `userId` 和角色固定为 `admin` | 让本期模型清楚，也为未来普通用户预留独立身份空间；只把登录用户名和密码作为可变凭据 |
| D-03 | 管理员凭据和会话共用一个服务拥有的认证状态 | 首次网页登录必须能原子写凭据并同时处理会话；继续使用 root 只读密码文件无法满足该行为 |
| D-04 | session secret 仍为 root 管理、服务只读的独立文件 | 服务需要验证 Cookie，但不需要改变签名根；管理员设置不旋转 secret，CLI reset-password 继续旋转并撤销全部会话 |
| D-05 | setup 显式选择 `password` 或 `login-token` | 自动从参数是否存在推断初始化方式会让自动化意图不清；令牌初始化必须同时显式启用长期令牌能力 |
| D-06 | token 格式为 `dsh_otl_v1_` 加 32 字节 base64url | 256 位熵抵抗猜测，固定前缀让格式和未来升级可区分；token 格式版本独立于安装 schema v2 |
| D-07 | 每个 token 使用独立摘要文件 | CLI 与服务进程无需共享内存或不可靠锁文件；SHA-256 文件名和无秘密元数据避免明文落盘 |
| D-08 | 兑换以同目录原子重命名抢占，先消费再建会话 | 并发只有一个成功；崩溃或后续写入失败时宁可用户重签，也不恢复 bearer token 形成重放窗口 |
| D-09 | URL 使用 fragment 桥接再同源 POST | fragment 不发送给边缘访问日志、Referer 或普通预取；GET 不消费，浏览器清除历史后用现有 CSRF 与 Origin 边界兑换 |
| D-10 | 所有 token 失败使用同一 401 结果 | 不向攻击者暴露格式、存在、过期或使用状态；429、CSRF 403 和方法 405 仍保留各自协议语义 |
| D-11 | 自定义失败文案按 zh/en 分开且只能是纯文本 | 延续现有双语界面，同时阻止 HTML、脚本和不受控外链进入认证页面 |
| D-12 | 管理员密码至少 15 字符，无组合规则 | 这是无 MFA 的管理员单因素口令；长口令优先于大小写或符号组合规则。密码不做 Unicode 规范化，避免静默改变秘密 |
| D-13 | Later 只影响当前令牌登录 | 不引入提醒调度和新持久状态；每次新的令牌登录在管理员未设置时重新提示 |
| D-14 | 首次设置保留当前会话并撤销其他启动会话 | 防止先前泄漏的 bootstrap 会话在管理员建立凭据后继续存活；当前用户无需重新登录 |
| D-15 | 已确认的通用参数改良纳入 v2 | `--json` 不改变交互、`--dsh-executable`、默认值一致、统一密码输入、全局 flag 和等号语法都是长期正确的契约；Nginx 专用参数随破坏性 v2 删除 |
| D-16 | 固定公网认证前缀 `/auth` | 安装器、Caddy、浏览器和签发 URL 使用一个公开路径，避免出现插件配置可变但边缘路由未同步的伪能力 |
| D-17 | systemd 自动发现；容器显式给认证状态和 public origin | 系统安装已有可信所有权记录。容器没有 systemd 发现事实，必须显式输入并做相同路径和权限校验 |
| D-18 | 固定标准 Caddy `v2.11.4` 为项目内置唯一公网边缘 | TLS、HTTP/2、WebSocket、SSE、下载和连接管理交给成熟运行时；项目不探测或复用用户 Caddy/Nginx，也不先维护通用 Go Gateway |
| D-19 | Caddy 与 TS 保持职责分离 | Caddy 只执行 TLS、连接、代理、大小和超时；TS 继续决定登录、会话、CSRF、Origin、限流和身份，避免边缘进程持有认证状态 |
| D-20 | Caddy 只从精确平台包离线安装 | x64/ARM64 包携带官方二进制、checksum、manifest 和许可证；setup 校验后复制，避免运行时下载和用户环境漂移 |
| D-21 | automatic TLS 默认，manual TLS 使用 systemd credentials | 默认降低安装门槛；手工私钥不进入配置和普通环境。独立 DynamicUser 服务、关闭 Admin API并拒绝接管冲突端口 |

## 状态一致性

运行中的插件是认证状态的唯一写者。网页登录在同一个内存快照中更新管理员和会话，再原子持久化。`reset-password` 是例外：它必须先让 DSH 服务停止或确认未运行，再备份、更新认证状态和 session secret、恢复服务；失败时按安装器日志回滚，不能与运行进程竞争写文件。

token 文件独立于认证状态。签发命令创建 token 文件；插件兑换时原子抢占并删除。认证状态创建会话失败不恢复 token。残留的抢占文件视为已消费，只能由严格命名和过期清理删除。

## 被拒绝的替代方案

- 查询参数直接 GET 兑换：会进入访问日志和浏览器历史，也容易被链接预取消费。
- 把 token 放入主认证 JSON：CLI 与运行服务会产生跨进程读改写竞争。
- Unix socket 签发：要求在既有 Harness 服务中新增管理监听器和生命周期，部署与容器契约更复杂。
- 最新 token 覆盖所有旧 token：会使云控制面的并发请求互相失效；受限容量和短 TTL 已控制暴露面。
- 首次设置后关闭令牌：不满足持续从云控制台免密进入实例的产品目标。
- 复用系统 Caddy/Nginx：版本、模块和用户配置不可控，会让安装和 doctor 结果不可复现。
- 自研通用 Go Gateway：当前没有 Caddy 无法表达的领域需求；只有标准配置的安全缺口得到证据后，才评估最小 `dsh-auth` Caddy 模块。

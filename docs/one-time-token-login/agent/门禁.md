# 项目门禁

门禁是授权条件，不是 Story 状态。所有分母固定；增加或删除条件需要用户确认并更新 Epic 意图。

## READY：可以开工（2 项）

1. npm latest Harness 已精确锁定、升级并通过统一检查、86 个测试、锁定/latest 真实 E2E；官方 release tag 扩展点可只读复核。
2. 最新已提交代码基线、Epic、七个 Story、执行卡、Caddy/v2 接口和安全矩阵通过结构检查且互相一致，主工作区没有重叠改动。

通过证据：Harness 版本/E2E JSON、官方 tag commit、基线 commit、分支、`git status --short`、`git worktree list`、专题脚本 `check` 和 `status --json`。当前为 `2/2`。

撤销规则：基线被重写，认证/schema/公开接口决策变化，覆盖项失去唯一主责，或出现重叠未提交改动时立即撤销。

## COMPONENT：各部分完成（6 项）

分母固定为 STORY-01、STORY-01.1 至 STORY-05 六个工程结果。每项通过条件：Story TODO 和验收全部满足；聚焦行为测试、受影响的代码健康检查和 `git diff --check` 通过；执行卡记录起止版本、失败证据、命令、退出码、副作用、清理和提交；后续 Story 输入唯一。

当前为 `0/6`。任何已通过组件在后续改动中出现相关测试失败、接口漂移、权限放宽或证据无法复现时撤销该项。

## RELEASE：可以发布（1 项）

唯一条件：STORY-06 在同一 acceptance commit 上固定当时 npm latest，完成锁定/latest Harness E2E、全量 `check`、Caddy 检查、打包、秘密扫描并逐项关闭矩阵；平台包、两种 TLS、systemd、容器、卸载重装和失败恢复文档与实际结果一致。

当前为 `0/1`。acceptance commit、npm latest、发布包、依赖、Caddy 二进制/配置、认证政策或部署说明变化时撤销，必须重新执行受影响检查；认证、schema 或破坏性协议变化触发完整 RELEASE 重验。

## 统一验证入口

```bash
corepack pnpm run check
corepack pnpm run check:caddy
corepack pnpm run test:e2e
corepack pnpm run test:e2e:latest-dsh
npm pack --dry-run
git diff --check
```

Story 迭代使用最窄聚焦测试，但不能用单元测试替代 RELEASE 的真实浏览器、Caddy、重启、打包和秘密扫描。
